# 【C++ 异常机制详解】零开销性能 + RAII 异常安全 + 网络重试示例（附代码）
`C++` 异常极致是**零开销正常路径 + 高开销异常路径**的设计，适合底层性能敏感场景，但不像 `Java` 那样到处抛
## 1. 异常的基本语法
- **throw：** 抛出异常（跳到匹配 catch）
```cpp
if(error)
{
	throw std::runtime_error("Something went wrong"); // 抛 sting 异常
}
```
- **try-catch：捕获异常**
	- **throw** 抛出的对象会匹配同类型最近的 **catch**
	- **throw** 跳到 **catch** 时，**throw** 后面的语句不再被执行（沿着调用链创建的对象都将析构（栈展开））
	- 抛出异常对象后，会生成一个异常对象的拷贝。因为抛出的异常对象可能是一个局部对象，所以会生成一个拷贝对象，这个拷贝的对象会在 **catch** 后销毁（类似于函数的传值返回），因为异常可能跨函数栈传播，拷贝确保安全
- **栈展开：**
	- 抛出异常后，程序暂停当前函数的执行，开始寻找匹配的 `catch` 子句，首先检查 `throw` 是否在 `try` 的里面，在就查找匹配的 `catch`语句
	- 如果当前函数没有 `try/catch`，或者 `try/catch` 不匹配，则退出当前函数，进行在外层函数中查找，上述查找的 `catch` 过程被称作**栈展开**。例如下面代码：`函数 Divide` 中 `b = 0` 则报错，抛出 `string` 类型的异常。同函数内，`catch` 为 `int` ，类型不匹配，跳出外层 `Func()` 函数。外层 `Func()` 找 `catch`， 外层`Func` 的 `catch` 为 `char*` 类型，继续跳出外层 `main` 函数。外层 `main` 函数的 `catch` 为 `string`类型，则找到匹配的 `catch` 子句，`catch` 子句代码会继续执行
	- 如果到达 `main` 函数，依旧没有找到匹配的 `catch` 子句，程序会调用标准库的 `terminate` 函数终止程序
```cpp
double Divide(int a, int b)
{
	try
	{
		if(b == 0) // 分母为零，抛异常
		{
			string s("Divide by zero condition1");
			throw s; // 异常为 string 类型，catch 需接受 string 类型
		}
		else
		{
			return ((double)a / (double)b);
		}
	}
	catch (int errid) // 接受 int 异常
	{
		cout << errid << endl;
	}
	
	return 0;
}

void Func()
{
	int len, time;
	cin >> len >> time;
	
	try
	{
		cout << Divide(len, time) << endl; // 进入 Divide 函数中找异常
	}
	catch(const char* errmsg) // 接受 char* 异常
	{
		cout << errmsg << endl;
	}
	
	cout << __FUNCTION__ << ":" << __LINE__ << endl;
}

int main()
{
	while(1)
	{
		try
		{
			Func(); // 进入 Func 函数中找异常
		}
		catch(const string& errmsg) // 接受 sting 类型异常
		{
			cout << errmsg << endl;
		}
	}
	
	return 0;
}
```
## 查找匹配的处理代码
- 如果有多个匹配类型，调用最近的 `catch`
- 例外：允许权限缩小
	- 非常量 --> 常量
	- 数组 --> 指向数组元素类型的指针
	- 函数 --> 指向函数的指针
	- 派生类 --> 基类类型（非常常用）
- 到 `main` 函数还没有异常匹配，我们不期望终止程序，会用 `chach(...)` 来进行任意类型异常的捕捉（但不知道异常错误）

| 场景       | 用异常？ | 为什么不/为什么是            |
| -------- | ---- | -------------------- |
| 网络发送失败重试 | 不要   | 可预期，用返回值 + 循环高效      |
| 内存分配失败   | 是    | 不可恢复，throw bad_alloc |

```cpp
{

	}
	else
	{
		cout << "HttpServer 调用成功" << endl;

}

{

	{
		// 每 1s 调用一次

		try
		{
			HttpServer();
		}
		catch (const Exception& e) // 捕获基类，基类对象和派生类对象都可被捕获

			cout << "Unkown Rxception" << endl;
```

## 异常重新抛出
有时 `catch` 到一个异常对象后，需要对错误进行分类，其中的某种异常错误需要进行特殊的处理，其他错误则重新抛出异常给外层调用链处理。捕获异常后需要重新抛出，直接 `throw` 就可以把捕获对象直接抛出
```cpp
#define _CRT_SECURE_NO_WARNINGS
#include<iostream>
using namespace std;

#include<thread>

class Exception
{
public:
	Exception(const string& errmsg, int id)
		:_errmsg(errmsg)
		,_id(id)
	{ }

	virtual string what() const
	{
		return _errmsg;
	}

	int getid() const
	{
		return _id;
	}

protected:
	string _errmsg;
	int _id;
};

class SqlException : public Exception
{

		:Exception(errmsg, id)
		, _sql(sql)
	{ }

	virtual string what() const

		str += _errmsg;
		str += "->";
		str += _sql;
		return str;

void _SendMsg(const string& s)
{
	if (rand() % 2 == 0)
	{
		throw HttpException("网络不稳定，发送失败", 102, "put");
	}
	else if (rand() % 7 == 0)
	{
		throw HttpException("你已经不是对方好友，发送失败", 103, "put");
	}
	else
	{
		cout << "发送成功" << endl;
	}
}

void SendMsg(const string& s)
{
	// 发送失败，重新发送3次
	for (int i = 0; i < 4; i++)
	{
		try
		{
			_SendMsg(s);
			break;
		}
		catch (const Exception& e)
		{
			// 捕获异常，if中是102号错误，网络不稳定，重新发送
			// 捕获异常，else中不是102号错误，则将异常重新抛出

			if (e.getid() == 102)
			{
				// 重新3次以后否则失败，需重新抛出异常
				if (i == 3)
					throw;

				cout << "开始第" << i + 1 << "重试" << endl;
			}
			else
			{
				throw;
			}
		}
	}
}

int main()
{
	srand(time(0));

	string str;
	while (cin >> str)
	{
		try
		{
			SendMsg(str);
		}
		catch (const Exception& e)
		{
			cout << e.what() << endl;
		}
		catch (...)
		{
			cout << "Unkown Exception" << endl;
		}
	}

	return 0;
}
```

## 异常安全问题
- 异常抛出后，后面的代码就不会再执行，前面申请了资源(内存，锁等)，后面进行释放，但是中间可能会抛异常就会导致资源没有释放，由于异常就引发资源泄漏。需要用到后面的智能指针部分。
- 析构函数也可能导致内存泄漏。原理：析构函数要释放10个资源，释放到第5个事抛出异常，捕获时会跳过，导致后面5个资源没有释放
```cpp
double Divide(int a, int b)
{
	// 当b == 0时抛出异常
	if (b == 0)
	{
		throw "Division by zero condition!";
	}
	return (double)a / (double)b;
}

void Func()
{
	// 这里可以看到如果发生除0错误抛出异常，另外下⾯的array没有得到释放。
	// 所以这里捕获异常后并不处理异常，异常还是交给外层处理，这里捕获了再
	// 重新抛出去。
	int* array = new int[10];

	try
	{
		int len, time;
		cin >> len >> time;
		cout << Divide(len, time) << endl;
	}
	catch (...)
	{
		// 捕获异常释放内存
		cout << "delete []" << array << endl;
		delete[] array;
		throw; // 异常重新抛出，捕获到什么抛出什么
	}
	cout << "delete []" << array << endl;
	delete[] array;
}

int main()
{
	try
	{
		Func();
	}
	catch (const char* errmsg)
	{
		cout << errmsg << endl;
	}
	catch (const exception& e)
	{
		cout << e.what() << endl;
	}
	catch (...)
	{
		cout << "Unkown Exception" << endl;
	}

	return 0;
}
```
## 异常规范
- C++98中过于复杂，建议直接学习C++11的方式
- C++11中，如果类型不会抛出异常，就在函数参数列表后加 `noexcept`
- 如果类型会抛异常，函数参数列表后面又加了 `noexcept`，重新会调用 `terminate` 终止程序
- `noexcept` 还可以作为一个运算符去检测表达式是否会抛出异常，可能会返回 `false`， 不会返回 `true`
# C++异常总结（性能视角+实际运用）
C++ 异常机制是**零开销正常路径 + 高开销异常路径**的设计，适合底层性能敏感场景（特斯拉车载软件常用），但不像 Java 那样到处抛。

**1.异常的基本语法：**
- **throw：** 抛出异常（跳到匹配 catch）
```cpp
if(error)
{
	throw std::runtime_error("Something went wrong"); // 抛 sting 异常
}
```
- **try-catch：捕获异常：**
```cpp
try {
        risky_function();
    } catch (const std::exception& e) {  // 捕获基类，处理所有派生异常
        std::cerr << e.what() << endl;  // what() 返回错误描述
    } catch (...) {  // 捕获所有其他异常
        std::cerr << "Unknown error" << endl;
    }
```
- **noexcept**：声明函数不抛异常（编译器优化）。
```cpp
void safe_func() noexcept { /* no throw */ }
```

**2.异常的性能代价：**

- **正常路径**：几乎 0 开销（编译器用异常表预计算，不影响执行流）。
- **异常路径**：高开销（栈展开 + 析构局部对象 + 跳转）。
    - 为什么贵？C++ 要求抛异常时自动调用所有局部对象的析构函数（RAII），这在栈深时很耗时。
- **疑惑解答**：网络发送失败的重试**不要用 throw/catch**（重复 throw 会让性能崩盘 + 代码丑陋）。
    - 正确写法：用返回值/循环重试（见下面示例）。
    - 异常只用在“不可恢复”场景（如内存尽了、socket 彻底坏了）。

3.**异常安全级别：（面试常考）**

- **Nothrow**：绝不抛（`noexcept`）。
- **Strong**：要么全成功，要么回滚（如 `vector::push_back`）。
- **Basic**：资源不漏，但状态可能乱。
- **None**：可能漏资源（别写）。

**4.实际使用示例：（网络重试场景）**

用错误码 + 循环（不抛异常）：
```cpp
enum class SendError { Success, Timeout, Fatal };

SendError send_msg(const Message& msg, int max_retries = 3) {
    for (int attempt = 0; attempt < max_retries; ++attempt) {
        // 模拟发送
        bool sent = try_send(msg);
        if (sent) return SendError::Success;
        if (is_fatal_error()) return SendError::Fatal;  // 不可恢复，返回错误码
        std::this_thread::sleep_for(std::chrono::milliseconds(100 * (attempt + 1)));
    }
    return SendError::Timeout;
}

// 使用
auto err = send_msg(my_msg);
if (err == SendError::Timeout) {
    // 外层处理：日志、通知用户
} else if (err == SendError::Fatal) {
    throw std::runtime_error("Network fatal error");  // 只在致命时抛
}
```

**5.异常小Tips：**

- 用 `RAII`（智能指针、`lock_guard`）保证异常安全。
- 异常传播时，栈展开自动析构局部对象。
- 避免异常：用 `optional / expected` (C++23) 处理错误。

**预热智能指针：**
智能指针是异常安全的守护神（RAII 实现）：
- **unique_ptr**：独占，零开销，`noexcept` 友好。
```cpp
unique_ptr<int> p = make_unique<int>(42);  // 自动 delete
``` 
- **shared_ptr**：共享计数，适合多所有者。
```cpp
shared_ptr<int> sp = make_shared<int>(42);  // 引用计数
``` 
- **weak_ptr**：弱引用，解决循环引用。
- 性能：`unique > shared` (计数开销)。

重点学习：如何在异常场景下用智能指针防止泄漏。
