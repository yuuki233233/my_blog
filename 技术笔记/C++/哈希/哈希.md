# 一、哈希概念
**哈希(hash)又称散列**，是一种组织数据的方式。通过**哈希函数把关键字Key跟存储位置建立一个映射关系**，查找是通过这个哈希函数计算出key存储位置，进行快速查找。
## 1.1 直接定址法
主要用于：关键字的范围比较集中。比如一组关键字在`[0,99]`之间，那么就开100个数的数组，每个关键值就是数组的下标。比如一组关键字值都在`[a,z]`的字母之间，那么我们开26个数的数组，每个关键字acsii码值就是存储位置的下标
## 1.2 哈希冲突
当关键字的范围比较分散时，用直接定址法就浪费内存，可能内存不够用。比如有`[0,9999]`数据范围的 N 个值，映射到一个 M 个空间的数组中（一般情况下 M >= N），那么我们就要借助哈希函数，关键字`key`被映射到对应数组的位置，要注意对需映射值计算出的值必须在`[0,M)`之间。
两个不同的`key`可能映射到同一个位置，就产生了哈希冲突
## 1.3 负载因子
哈希表：大小->M，存储->N。负载因子：`N/M`
- 负载因子越大，哈希冲突的概率越高，空间利用率越高
- 相反负载因子越小，哈希冲突的概率越低，空间利用率越低
当**负载因子 >= 0.7**时就可以考虑给哈希表扩容
## 1.4 将关键字转为整数
我们将关键字映射到数组中的位置，一般时整数。如果是字符串，就将每个字母的ASCII码值相加，再放到对应数组的位置
## 1.5 哈希函数
可以让N个关键字被等概率散列分布到哈希表的M个空间中
### 1.5.1 除法散列法/除留余数法
- 假设哈希表大小为 `M`。映射位置的下标：`h(key) = key % M`
- 使用除法散列表，最好使用素数作为数组空间大小，尽量避免为2的次方和10的次方
- 数组大小为素数，是为了让更多的位置参与运算，映射出来的值产生的冲突概率越小
## 1.6 处理哈希冲突
实践中，一般选择除法散列表作为哈希函数。当发生冲突时可以选择**开发定址法和链地址法**
### 1.6.1 开发定址法
在开放定址法中所有的元素都放到哈希表里，当一个关键字key用哈希函数计算出的位置冲突了，则按照某种规则找到一个没有存储数据的位置进行存储，开放定址法中负载因子一定是小于的。这里的规则有三种：线性探测、二次探测、双重探测。
#### 线性探测
- 从发生冲突的位置开始，依次线性向后探测，直到寻找到下一个没有存储数据的位置为止，如果走到哈希表尾，则回绕到哈希表头的位置。
- `hash0 = key % M`，hash0位置冲突了，则线性探测公式为:`hashi = (hash0+i) % M`，因为负载因子小于1,则最多探测M-1次，一定能找到一个存储key的位置。
- 线性探测的比较简单且容易实现，线性探测的问题假设，hasho位置连续冲突，hasho，hash1，hash2位置已经存储数据了，后续映射到hash0，hash1，hash2，hash3的值都会争夺hash3位置，这种现象叫做群集/堆积。下面的二次探测可以一定程度改善这个问题。
>下面演示`{19, 30, 5, 36, 13, 20, 21, 12}`这一组值映射到`M = 11`的表中
>![](图片/线性探测1.png)
>`h(19) = 8, h(30) = 8, h(5) = 5, h(36) = 3, h(13) = 2, h(20) = 9, h(21) = 10, h(12) = 1`
>![](图片/二次探测.png)
#### 二次探测
- 从发生冲突的位置开始，依次左右按二次方跳跃式探测，直到寻找到下一个没有存储数据的位置为止，如果往右走到哈希表尾，则回绕到哈希表头的位置；如果往左走到哈希表头，则回绕到哈希表尾的位置；
- `hash0 = key % M`，hash0位置冲突了，则二次探测的公式为：`hashi = (hash0 + i*i) % M`
- 二次探测，当`hashi = (hash0 - i*i) % M`时，`hashi < 0时，需要hahsi += M`
>下面演示`{19, 30, 52, 63, 11, 22}`这一组值映射到`M = 11`的表中
>![](图片/线性探测1.png)
>`h(19) = 8, h(30) = 8, h(52) = 8, h(63) = 8, h(11) = 0, h(22) = 0`
>![](图片/线性探测2.png)
### 1.6.2 开发定址法代码实现
#### （1）线性探测
初始数组大小(N)应为素数，是为了让更多的位置参与运算，映射出来的值产生的冲突概率越小
存储位置：数据大小(key) % 数组大小(N)
-  若存在冲突，用线性探测
	-  找需插入的位置
	-  如位置被占，需线性探测(如越界，需取模)
	-  找到空位置/删除位置，放入位置，状态设为存在
	-  节点个数++
```cpp
bool Insert(const pair<K, V>& kv)
	{
		Hash hash;
		size_t hash0 = hash(kv.first) % _tables.size(); // 插入位置
		size_t hashi = hash0;
		size_t i = 1; // 线性探测
		int flag = 1; // 二次探测需用到正负
		while (_tables[hashi]._state == EXIST)
		{
			// 线性探测
			hashi = (hash0 + i) % _tables.size(); // 寻找位置
			++i;

			// 二次探测
			/*hashi = (hash0 + (i*i*flag)) % _tables.size();
				if (hashi < _tables.size())
					hashi += _tables.size();

				if (flag == 1)
				{
					flag = -1;
				}
				else
				{
					++i;
					flag = 1;
				}*/
		}
		_tables[hashi]._kv = kv;        // 找到位置
		_tables[hashi]._state = EXIST;  // 状态设为存在

		return true;
	}
```
要注意的是，这里需要给每个存储值的位置加一个状态标识，否则删除一些值以后，会影响后面冲突的值查找。如下图，删除30，会导致查找20失败，当我们给每个位置加一个状态标识`{EXIST, EMPTY, DELETE}`，删除30就可以直接把状态改为`DELETE`，查找遇到`EMPTY`即可找到20
#### （2）扩容
若冲突因子>=0.7，则扩容 (创建新数组，将旧数组的数据插入到新数组，然后交换数组)。如果是二倍扩容，下一个就不是质数了，那要怎么解决呢?
1. 方案一：根据java中实现的除法散列表中，使用2的整数幂，但是计算通过位运算
2. 方案二：sgi版本的哈希表使用方法，给了一个近似2倍的质数表，每次取质数表获取扩容后的大小
```cpp
// 统计相差大概2倍的素数(用于数组扩容)

{
	// Note: assumes long is at least 32 bits.
	static const int __stl_num_primes = 28;
	static const unsigned long __stl_prime_list[__stl_num_primes] = {
		53, 97, 193, 389, 769,
		1543, 3079, 6151, 12289, 24593,
		49157, 98317, 196613, 393241, 786433,
		1572869, 3145739, 6291469, 12582917, 25165843,
		50331653, 100663319, 201326611, 402653189, 805306457,
		1610612741, 3221225473, 4294967291
	};
	const unsigned long* first = __stl_prime_list;
	const unsigned long* last = __stl_prime_list + __stl_num_primes;
```

#### （3）key不能取模的问题
当key是string/Date等类型时，key不能取模，那么我们需要给HashTable增加一个仿函数，这个仿函数支持把key转换成一个可以取模的整形，如果key可以转换为整形并且不容易冲突，那么这个仿函数就用默认参数即可，如果这个Key不能转换为整形，我们就需要自己实现一个仿函数传给这个参数，实现这个仿函数的要求就是尽量key的每值都参与到计算中，让不同的key转换出的整形值不同。string做哈希表的key非常常见，所以我们可以考虑把string特化一下。
```cpp
// 仿函数（绝对值）
template<class K>
struct HashFunc
{
	size_t operator()(const K& key)
	{
		return (size_t)key;
	}
};

// 仿函数（字符串比较）
template<>
struct HashFunc<string> // 模板特化
{
	// 字符串转换成整形，可以把字符ASCII码值相加
	// 但是直接相加的话，"abcd"和"bcad"计算出的ASCII码值相同
	// 这里我们使用BKDR哈希的思路，用上次的计算结果取乘一个质数，这个质数一般是31，131
	size_t operator()(const string& s)
	{
		size_t hash = 0;
		for (auto ch : s)
		{
			hash += ch;
			hash *= 131; // abc 与 cba 的ACSII码值一样
					     // 这里乘131是为了分辨出大小
		}

		return hash;
	}
};
```

```cpp
	{
		Hash hash;
		size_t hash0 = key % _tables.size();
		size_t hashi = hash0;
		size_t i = 1;
		while (_tables[hashi]._state != EMPTY)
		{
			if (_tables[hashi]._state == EXIST
				&& _tables[hashi]._kv.first == key)
			{

		{
			return false;
		}

	size_t _n = 0; // 记录插入节点数量
```

### 1.6.3 链地址法
#### （1）链接节点
哈希表中每一个格都存个指针，指针为`NULL`就无映射，反之有映射。多个冲突值可以链接成一个链表，挂再哈希表相应位置的下面，链地址法也叫做拉链法或哈希桶
>下面演示`{19, 30, 5, 36, 13, 20, 21, 12, 24, 96}`这一组值映射到`M = 11`的表中
>![](图片/线性探测1.png)
>`h(19) = 8, h(30) = 8, h(5) = 5, h(36) = 3, h(13) = 2, h(20) = 9, h(21) = 10, h(12) = 1, h(24) = 2, h(96) = 8`
>![](图片/哈希桶.png)
```cpp
bool Insert(const pair<K, V>& kv)
{
	size_t hashi = kv.first % _tables.size();
	// 头插
	Node* newnode = new Node(kv);
	newnode->_next = _tables[hashi];
	_tables[hashi] = newnode;
	++_n;

	return true;
}
```

#### （2）扩容
开放地址法负载因子必须小于1，链地址法的负载因子就没有限制。负载因子越大，哈希冲突的概率越高，空间利用率越高；相反负载因子越小，哈希冲突的概率越小，空间利用率越低。stl中unordered最大负载因子基本控制在1，大于1就扩容
```cpp
// 负载因子 == 1时扩容
if (_n == _tables.size())
{
	vector<Node*> newTable(_tables.size() * 2);
	for (size_t i = 0; i < _tables.size(); ++i)
	{
		Node* cur = _tables[i];
		while (cur)
		{
			Node* next = cur->_next;
			// 新表的位置
			size_t hashi = kv.first % newTable.size();
			cur->_next = newTable[hashi];
			newTable[hashi] = cur;

			cur = next;
		}

		_tables[i] = nullptr;
	}

	_tables.swap(newTable);
}
```
