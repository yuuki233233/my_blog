## 进程优先级
### 基本概念
- 现实中，吃饭排队、取票排队看病等，这都是一个优先级
- 在计算机中，也就是进程得到cpu资源的先后顺序
- 优先级高的进程优先执行
- 也可以把不重要的进程运行到指定 CPU 上，大大改善系统整体性能

### 查看系统进程

系统怎么知道我们访问文件的时候，是拥有者、所属组、还是 other
我们看下列的文件是如何识别权限的：
```bash
[zjh@izj6cd3zr5adf6jnm3mwihz ~]$ ps -al | head -1 && ps -al | grep myproc
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1001 16257 15603  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc
1 S  1001 16258 16257  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc

[zjh@izj6cd3zr5adf6jnm3mwihz lesson14]$ ll
total 20
-rw-rw-r-- 1 zjh zjh   80 Mar 27 20:56 Makefile
-rwxrwxr-x 1 zjh zjh 8768 Mar 30 09:36 myproc
-rw-rw-r-- 1 zjh zjh  478 Mar 30 09:35 myprocess.c


[zjh@izj6cd3zr5adf6jnm3mwihz lesson14]$ ls -ln
total 20
-rw-rw-r-- 1 1001 1001   80 Mar 27 20:56 Makefile
-rwxrwxr-x 1 1001 1001 8768 Mar 30 09:36 myproc
-rw-rw-r-- 1 1001 1001  478 Mar 30 09:35 myprocess.c
```

- UID：代表执行者的身份。`UID = zjh = 1001`，Linux系统中，访问任何资源，都是进程访问，1001进程代表用户
- PID：代表这个进程的代号
- PPID：这个进程是由哪个进程衍生而来
- PRI：进程可被执行的优先级，越小优先级越高
- NI：进程的nice值
进程真实的优先级 = PRI + NI

### PRI & NI

#### 查看进程优先级命令

用 top 命令更改已存在进程的 nice：
1. top
2. 进入top后按 r
3. 输入进程 pid
4. 输入 nice 值

额外修改进程优先级命令：nice，renice

#### 优先级查看
输入 NI = 10，PRI 从默认的80 -> 90（优先级变低了）
```bash
[zjh@izj6cd3zr5adf6jnm3mwihz lesson14]$ ps -al | head -1 && ps -al | grep myproc
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1001 16298 15603  0  90  10 -  1054 hrtime pts/1    00:00:00 myproc
1 S  1001 16299 16298  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc
```

操作系统为了安全，让普通用户不能频繁得修改进程优先级，此时想再修改，需要用到 root 用户
重复改优先级步骤，将 NI 改为 -10
```bash
[root@izj6cd3zr5adf6jnm3mwihz ~]# ps -al | head -1 && ps -al | grep myproc
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1001 16298 15603  0  70 -10 -  1054 hrtime pts/1    00:00:00 myproc
1 S  1001 16299 16298  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc
```

#### 优先级极限范围

把进程的 nice 值改为 -100，但只取到了 nice = -20
```bash
[root@izj6cd3zr5adf6jnm3mwihz ~]# renice -n -100 -p 16298
16298 (process ID) old priority -10, new priority -20

[root@izj6cd3zr5adf6jnm3mwihz ~]# ps -al | head -1 && ps -al | grep myproc
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1001 16298 15603  0  60 -20 -  1054 hrtime pts/1    00:00:00 myproc
1 S  1001 16299 16298  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc
```

把进程的 nice 值改为 100，但只取到了 nice = 19
```bash
[root@izj6cd3zr5adf6jnm3mwihz ~]# renice -n 100 -p 16298
16298 (process ID) old priority -20, new priority 19

[root@izj6cd3zr5adf6jnm3mwihz ~]# ps -al | head -1 && ps -al | grep myproc
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1001 16298 15603  0  99  19 -  1054 hrtime pts/1    00:00:00 myproc
1 S  1001 16299 16298  0  80   0 -  1054 hrtime pts/1    00:00:00 myproc
```

由上面数据，所以Linux进程的优先级范围 PRI 是 [60, 99]

为什么限制进程优先级范围呢？
因为优先级设立不合理，会导致优先级低的进程，长时间得不到 CPU 资源，进而导致：进程饥饿

### 进程竞争、独立、并行、并发

- 竞争性：硬件是少数的，而**进程是多数的**，使用资源的进程之间，必然是竞争关系，所以就有了**优先级和权限**的概念
- 独立性：进程 = PCB（内核数据结构） + 代码和数据，进程运行需要独享各种资源，多进程运行期间互不干扰。（如果你的VS2022崩溃了，对你的Github没有影响）
- 并行：双 CPU 计算机，多个进程在多个 CPU 下分别同时运行
- 并发：一个 CPU 打开多个进程（VS，Github...）同时在跑，其实只有一个进程在运行。那是因为多个进程**以毫秒**的时间来回切换，通过**切换**的方式，在一段时间内，多个进程同时推进
