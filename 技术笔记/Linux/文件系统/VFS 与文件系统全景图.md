
# 从宏观视角看：进程与文件的关系

最后，我们把视角拉回到最初的那个问题：【我们怎么通过 `open()` 拿到文件描述符，最后又是怎么变成对磁盘扇区的操作的？】

在 Linux 内核中，通过 **VFS（虚拟文件系统）** 这一层多态的设计，把进程和物理磁盘完美串联了起来。看最后两张终极结构体，梳理过程如下：

## 1. VFS 架构链路

![](图片/文件系统总结图4%201.png)

当你在代码中调用 `open("/home/a.txt")` 时，发生的事情远超你想象：
1.  **进程层**：`task_struct` 包含 `files_struct`，指向当前进程打开的 fd 数组。
2.  **路径解析（dentry）**：内核通过 `dentry` 缓存或去磁盘解析路径，找到目标文件的 inode 结构。
3.  **文件对象（file）**：在系统内存中创建一个 `struct file` 结构体，挂载到 `fd_array[fd]` 上。`file` 内部通过 `f_dentry` 关联到目录项，同时它的 `f_op` 指针指向 `file_operations` 函数集（如 read/write）。
4.  **inode 层**：`file` 通过 `dentry` 找到了真实的 `inode`。`inode` 也有一个 `i_op` 指针，指向各种操作函数。
5.  **超级块（super_block）**：inode 隶属于一个特定的 super_block（代表一个已挂载的分区）。
6.  **物理层**：通过 inode 的 `i_block` 以及 super_block 记录的底层设备信息，最终把数据请求下发给磁盘驱动，转化为对磁盘 LBA 扇区的读写。

## 2. 一切皆文件的精髓：多态（C语言实现）

为什么 Linux 能把键盘、显示器、磁盘等外设抽象成文件？
就是因为无论底层的硬件怎么变，VFS 只要求它们实现 `file_operations` 中的 `read`、`write` 等函数指针
- 对于普通磁盘文件：`read` 调用 Ext2 的读取算法，读取磁盘块。
- 对于键盘（字符设备）：`read` 调用键盘驱动的中断处理程序。
- 对于网卡（网络设备）：`write` 调用网络协议栈的发送函数。

**进程只需要认准文件描述符（fd）和 `file_operations` 接口。至于底层磁盘，内存还是网卡，VFS 帮你在中间做了解耦和分发**。

## 总结

回顾这一路，从磁盘上的最小物理单元（扇区），到抽象成 LBA 一维数组，再被文件系统划分为 Block 和 inode。最后通过 VFS 的 `dentry`、`file` 和 `file_operations` 挂接在进程的 `task_struct` 之上。

这就是 Linux 文件系统底层实现的手段。
