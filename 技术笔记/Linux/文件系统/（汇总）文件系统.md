# 一、磁盘的物理结构

机械磁盘是计算机中唯一一个纯粹的机械设备。它的结构可以看做“写字”和“读字”
- **盘片（Platter）**：相当于纸，表面涂有磁性材料，数据就存储再这里。
- **主轴（Spindle）**：带动盘片高速旋转（每分钟几千到上万次）。
- **磁头（Head）**：相当于笔，悬浮在盘片表面，负责读取和写入数据。每一个盘片都有一个磁头。
- **磁头臂（Boom）**：把所有磁头连在一起。**注意，所有磁头都是“共进退”的，同一时刻都在同一半径的同心圆上。**

![360](图片/硬盘拆开图.png)

基于物理结构，我们有零一下几个概念：
1. **磁道（Track）**：盘片旋转时，磁头不同，划出的一个同心圆。
2. **扇区（Sector）**：把磁道切成一段一段，这是磁盘读写的基本单位，通常是 **512 字节**。
3. **柱面（Cylinder）**：所有盘面上相同的半径的磁道，在逻辑上组成圆柱体。

![364](图片/磁盘物理存储结构图.png)

**CHS 寻址**：传统找数据的方式是，先找柱面（C）、再找磁盘（H）、最后找扇区（S）。这就叫 CHS 地址。

# 二、磁盘的逻辑结构（从三维到一维）

CHS 的三维寻址对操作系统来说太麻烦了。于是，硬件帮我们做了一层抽象：
**我们把磁盘想象成一条长长的磁带，将其“拉直”**。

这样，磁盘就成了一条巨大的**一维数据**。数组的每一个元素就是一个扇区（512字节）。这个一维数据的索引（下标），就叫做 **LBA（Logical Block Address，逻辑块地址）**。

- **硬件层**：磁盘自己负责在内部把 LBA 转换回 CHS 去找物理地址。
- **操作系统层**：OS 完全不需要管柱面磁头，**只需要把 LBA 当作数组下标使用**，想读哪个扇区就直接读。

>[!tip] **引入“块”的概念（Block）**：
>如果 OS 每次都只读 512 字节（一个扇区），效率太低（犹如去图书馆借书都只借一张纸）。所以 OS 将读取多个扇区（通常是 8 个扇区，即 **4KB**）作为一个“块”（Block）。
>**块是文件系统读写的最小单位**。我们后面讲的“数据块”，都是指这个 Block。

# 三、Ext2 文件系统：Linux 数据存储

文件 = 内容 + 属性。内容好说，按块存储就行。**但属性存哪？又怎么把属性和内容绑在一起？**

这就引出了 Linux 最核心的设计：**文件系统分区（Partition）与格式化**。从 Windows 来看，会有⼀块磁盘并且将它分区成C，D，E盘。分区从实质上就是对硬盘的一种格式化。
当我们将一个分区格式化为 Ext2 文件系统时，它会被划分为无数个**块组（Block Group）**。只要搞清楚一个块组的内部结构，就搞懂了整个文件系统。

![](图片/Ex2文件系统图.png)

>[!tip] **我们想要在硬盘上储文件，必须先把硬盘格式化为某种格式的文件系统，才能存储文件。文件系统的目的就是组织和管理硬盘中的文件。** 

## 3.1 块组（Block Group）的内部解剖

每个块组都有以下几个核心组成部分：
1.  **超级块（Super Block）**：记录整个分区的全局信息（inode总数、空闲块总数、块大小等）。如果它坏了，整个分区就废了。所以一般在每个块组都有备份。
2.  **GDT（块组描述符表）**：描述每个块组的属性（从哪里开始是 inode 表，哪里是数据块）。
3.  **Block Bitmap（块位图）**：一个巨大的 bitmap，用 0 和 1 记录哪些数据块被占用了，哪些是空闲的。
4.  **Inode Bitmap（Inode 位图）**：同理，记录哪些 inode 被占用了。
5.  **Inode Table（Inode 表）**：重点！**存放文件属性（大小、权限、时间、数据块指针）的表**。每个文件都有一个唯一的 inode 结构体存放在这里。**inode 编号以分区为单位，整体划分，不可跨分区**
6.  **Data Blocks（数据区）**：真正存放文件内容的地方。**Block 号按照分区划分，不可跨分区**

### 1.  `inode` 和 `datablock` 映射

inode 内部存在 `__le32 i_block[EXT2_N_BLOCKS]; /* Pointers to blocks */`，`EXT2_N_BLOCK = 15`，用来进行 inode 和 block 映射。这样文件 = 内容 ＋ 属性，都能被找到。

![](图片/inode%20和%20datablock%20映射.png)

> **inode 逻辑结构的核心结论**：
> 文件名不存 inode 里，inode 里存的是一堆指针（`i_block[15]`），指向数据区里真正的数据块。我们平时用 `ls -i` 看到的数字，就是这个文件在 Inode Table 里的下标！

>[!tip] 知道 inode 的情况下，是如何查找到文件属性和内容？
>- 分区之后的格式化操作，就是对分区进行分组，在每一个分组中写入 SB、GDT、Block、Bitmap、Inode Bitmap等管理信息，这些管理信息统称：文件系统。
>- 只要知道文件 inode，就能在指定分区中确定是哪一个分组，从而在分组里确定是哪个 inode。
>- 拿到 inode，也就拿到文件属性和内容。

### 2. 文件操作在 inode 层面到底做了什么？

- **新建文件（touch）**：
	1. 找空闲的 inode 号（查 Inode Bitmap），初始化文件属性（时间、大小等）。
	2. 找空闲的 Data Block 存放数据（查 Block Bitmap），把数据块地址填入 inode 的 `i_block`。
	3. 在父目录的数据块中，记录下【文件名 -> inode 号】的映射。
- **删除文件（rm）**：
	1. 发父目录的数据块中，抹去该文件名对应的记录。
	2. inode 的硬链接数减 1。
	3. 若硬链接数变为 0，则将 Inode Bitmap 和 Block Bitmap 中对应的位清空，释放空间。
- **查看文件（cat）**：
- 通过目录找到文件名对应的 inode，用 `i_block` 中的指针找到数据，把数据读如内存。

>[!tip] **经典面试题**：为什么在 Linux 中删除了一个巨大的日志文件，磁盘空间却没有释放？
>因为如果你是用 `rm` 删除了文件，但如果另一个进程（比如你的服务程序）还在打开着这个文件（持有 fd），文件 inode 的  `links_count` 变为 0，但 `f_count`（打开引用计数）还不为 0，OS 会保留文件数据块，防止程序崩溃。**解决办法：重启该进程，或利用 `>filename` 清空内容**。



#### 示例：创建文件 abc

```bash
[root]#touch abc
[root]# ls -i abc
263466 abc
```

![](图片/文件在底层的创建过程%201.png)

创建一个新文件主要有一下 4 个过程
1. **存储属性**：内核先找到一个空闲的 `inode` 节点。内核记录文件信息。
2. **存储数据**：该文件需要存储在三个磁盘块，内核找到了三个空闲块：图里为 300，500，800。将内核缓冲区的第一块数据复制到 300，下一块复制到500，以此类推。
3. **记录分配情况**：文件内容按顺序 300，500，800 存放。内核在 inode 上的磁盘分区记录了上述块列表。
4. **添加文件名到目录**：新的文件名 abc。内核将入口（263466, abc）添加到目录文件。文件名和 inode 之间的对应关系将文件名和文件的内容及属性连接起来。

## 3.2 目录的本质：文件名与 inode 映射

一个很颠覆认知的事实：**在磁盘的物理层面上，是没有“目录（文件夹）”这个概念的**
目录本质上也是一个文件。它有自己的 inode 和 Data Block。**只不过，目录这个文件的数据块里，存放的内容是：该目录下所有文件的【文件名】和【inode 号】的映射表。**

这就解释了：
*   我们平时找文件，靠的是**路径+文件名**。
*   系统通过目录文件的内容，把文件名解析成 inode 号。
*   拿着 inode 号去 Inode Table 里找到文件属性，顺藤摸瓜找到 Data Block，读出文件内容。

## 3.3 路径解析与挂载

既然访问文件必须知道 inode，那我们打开 `/home/test/a.txt` 时：
1. 系统先找到根目录 `/` 的 inode（根目录 inode 号固定为 2）。
2. 读取根目录的数据块，找到 `home` 这个目录名对应的 inode。
3. 进入 `home` 的 inode，读取它的数据块，找到 `test` 的 inode。
4. 最终找到 `a.txt` 的 inode。

这个过程叫**路径解析**。为了加速，Linux 内核在内存中维护了一个 `struct dentry` 树，把最近用过的路径缓存起来，避免每次都去磁盘上读目录。

![](图片/dentry树指向图.png)

**挂载（Mount）**：当你有多个分区时，它们有各自的根目录。Linux 通过将分区“挂载”到某个空目录（如 `/mnt/mydisk`），把不同分区的文件系统连成一棵巨大的树，统一管理。

# 四、软链接与硬链接

我们平时用 `ln` 命令可以创建链接。分为硬链接和软连接，它们在 inode 层面的表现完全不同。

## 4.1 硬链接（Hard Link）

`ln abc def`
- **原理**：并没有新建 inode，而是让 `def`  这个名字 -> `abc` 的inode。在目录的数据块中，新增了一行 `def` <-> inode编号。
- **特征**：inode 的 `i_link_count`（硬链接数）会 +1。当你删除 `abc` 时，只是把 `links_count` -1。只有减到 0 时，数据块才会真正被释放。
- **限制**：不能跨分区（inode 也不能跨分区）。不能对目录创建硬链接（防止死循环）。

## 4.2 软连接（Soft Link）

`ln -s abc def`
- **原理**：新建了一个全新的文件 `def`（有自己的 inode 和数据块）。只不过 `def` 的数据块里存的内容，是 `abc` 的路径字符串。
-  **特征**：类似 Windows 的快捷方式。如果你删除了 `abc`，`def` 还在，但它会变成死链接（找不到目标）。

## 4.3 软硬连接对比

- 软连接是独立的文件。
- 硬链接只是文件名和目标文件 inode 的映射关系。

## 4.4 软硬连接的用途

**硬链接**
- `.` 和 `..` 是硬链接。
- 文件备份。

**软连接**
- 类似快捷方式。

# 五、从宏观视角看：进程与文件的关系

最后，我们把视角拉回到最初的那个问题：【我们怎么通过 `open()` 拿到文件描述符，最后又是怎么变成对磁盘扇区的操作的？】

在 Linux 内核中，通过 **VFS（虚拟文件系统）** 这一层多态的设计，把进程和物理磁盘完美串联了起来。看最后一张终极结构体，梳理过程如下：

## 5.1 VFS 架构链路

![](图片/文件系统总结图4%201.png)

当你在代码中调用 `open("/home/a.txt")` 时，发生的事情远超你想象：
1.  **进程层**：`task_struct` 包含 `files_struct`，指向当前进程打开的 fd 数组。
2.  **路径解析（dentry）**：内核通过 `dentry` 缓存或去磁盘解析路径，找到目标文件的 inode 结构。
3.  **文件对象（file）**：在系统内存中创建一个 `struct file` 结构体，挂载到 `fd_array[fd]` 上。`file` 内部通过 `f_dentry` 关联到目录项，同时它的 `f_op` 指针指向 `file_operations` 函数集（如 read/write）。
4.  **inode 层**：`file` 通过 `dentry` 找到了真实的 `inode`。`inode` 也有一个 `i_op` 指针，指向各种操作函数。
5.  **超级块（super_block）**：inode 隶属于一个特定的 super_block（代表一个已挂载的分区）。
6.  **物理层**：通过 inode 的 `i_block` 以及 super_block 记录的底层设备信息，最终把数据请求下发给磁盘驱动，转化为对磁盘 LBA 扇区的读写。

## 5.2 一切皆文件的精髓：多态（C语言实现）

为什么 Linux 能把键盘、显示器、磁盘等外设抽象成文件？
就是因为无论底层的硬件怎么变，VFS 只要求它们实现 `file_operations` 中的 `read`、`write` 等函数指针
- 对于普通磁盘文件：`read` 调用 Ext2 的读取算法，读取磁盘块。
- 对于键盘（字符设备）：`read` 调用键盘驱动的中断处理程序。
- 对于网卡（网络设备）：`write` 调用网络协议栈的发送函数。

**进程只需要认准文件描述符（fd）和 `file_operations` 接口。至于底层磁盘，内存还是网卡，VFS 帮你在中间做了解耦和分发**。

# 总结

回顾这一路，从磁盘上的最小物理单元（扇区），到抽象成 LBA 一维数组，再被文件系统划分为 Block 和 inode。最后通过 VFS 的 `dentry`、`file` 和 `file_operations` 挂接在进程的 `task_struct` 之上。

这就是 Linux 文件系统底层实现的手段。
