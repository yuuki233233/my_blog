# 静态链接：地址修补

当我们有多个 `.o` 文件时，它们互相不知道对方存在的。

如果你用 `objdump -d code.o` 反汇编目标文件，你会发现调用外部函数（如 `printf` 或另一个文件里的 `run`）的 `call` 指令，后面的地址**全是 0**！

```bash
$ objdump -d code.o

code.o: file format elf64-x86-64  

Disassembly of section .text:  

0000000000000000 <run>:  
	0: f3 0f 1e fa endbr64  
	4: 55 push %rbp  
	5: 48 89 e5 mov %rsp,%rbp
	8: 48 8d 3d 00 00 00 00 lea 0x0(%rip),%rdi  # f<run+0xf>  
	f: e8 00 00 00 00 callq 14 <run+0x14>  # 地址全零
	14: 90 nop  
	15: 5d pop %rbp  
	16: c3 retq


$ objdump -d hello.o

hello.o: file format elf64-x86-64  


Disassembly of section .text:  

0000000000000000 <main>:  
	0: f3 0f 1e fa endbr64  
	4: 55 push %rbp  
	5: 48 89 e5 mov %rsp,%rbp  
	8: 48 8d 3d 00 00 00 00 lea 0x0(%rip),%rdi # f<main+0xf>  
	f: e8 00 00 00 00 callq 14 <main+0x14>  # 地址全零
	14: b8 00 00 00 00 mov $0x0,%eax
	19: e8 00 00 00 00 callq 1e <main+0x1e> # 地址全零
	1e: b8 00 00 00 00 mov $0x0,%eax
	23: 5d pop %rbp  
	24: c3 retq
```

- `objdump -d` 命令：将代码段（.text）进行反汇编查看
- `hello.o` 中的 `main` 函数不认识 `printf` 和 `run` 函数
```bash
$ cat hello.c
#include<stdio.h>

void run();

int main()
{
	printf("hello world!\n"):
	run();
	return 0;
}
```
- `code.o` 不认识 `printf` 函数
```bash
$ cat code.c
#include<stdio.h>
void run()
{
	printf("running...\n");
}
```

为什么全是 **0**？因为编译器在编译 `hello.c` 是，根本不知道 `run` 函数会在哪里，所以只能先填 0。同时，在 `.data` 段里留了一个**重定位表**，这张表将来在链接时，就会根据表里的记录的地址将其修正

### 链接器（Linker）的工作

**静态链接的本质，就是把所有的 `.o` 文件进行合并，并进行地址重定位**

1. **合并段**：把所有 `.o` 的 `.text` 合并成最终的 `.text`，`.data` 合并成最终的 `.data`。合并后，每一个函数的相对位置就确定了，从而计算出最终的**绝对虚拟地址**
2. **修补地址**：链接器拿着重定位表，找到那些填 0 的 `call` 指令，把它们替换成刚刚计算出的正确虚拟地址

**结论**：静态链接生成的程序，在**编译时**就已经把所有的代码的地址写死了。所以它不需要动态链接器，直接把可执行文件扔进内存就能跑。这就是为什么它的体积大，但运行快。

静态链接就是把库中的 `.o` 进行合并，和上述过程一样

所以链接其实就是将编译之后的所有目标文件连同用到的一些静态库运行时库组合，拼装成一个独立的可执行文件。其中就包括我们之前提到的地址修正，当所有模块组合在一起之后，链接器会根据我们的 `.o` 文件或者静态库中的重定位表找到那些需要被重定位的函数全局变量，从而修正它们的地址。这就是**静态链接**的过程。
