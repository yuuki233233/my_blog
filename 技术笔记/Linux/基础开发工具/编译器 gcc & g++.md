# 编译器 GCC/G++：代码是如何变成程序的？

## 编译器处理代码过程

我们写的 `.c` 文件只是一堆文本，机器根本看不懂。GCC 把它变成可执行文件，需要经历 **4 个阶段**：

1. **预处理（-E）**：展开头文件、宏替换、去注释。生成 `.i` 文件。
2. **编译（-S）**：把 C 代码翻译成汇编语言。生成 `.s` 文件。
3. **汇编（-c）**：把汇编翻译成机器能懂的二进制代码。生成 `.o` 目标文件。
4. **链接**：把多个 `.o` 文件和库文件打包在一起，生成最终的可执行文件。

> **小知识**：大型工程通常先由编译器把各个文件单独编译成 `.o` 文件，再统一链接。这样修改了某个文件，只需重新编译那一个 `.o`，而不必全盘重编，极大提升了效率。

**gcc编译选项**
```bash
gcc [选项] 要编译的文件 [选项] [目标文件]
```

**多个文件：** 将全部 `.c` 打包成 `.o`
```bash
gcc code.o code1.o code2.o -o code
```

### 3.1 动态链接 vs 静态链接

- **静态链接（静态库 `.a`）**：把库代码直接“拷贝”进可执行文件。
    - 优点：运行快，不依赖外部环境。
    - 缺点：文件体积巨大，内存中会有多份重复代码，库更新了必须重新编译。
    
- **动态链接（动态库 `.so`）**：只记录库的地址，运行时由操作系统加载库。
    - 优点：文件小，节省内存和磁盘，库更新方便。
    - 缺点：如果运行环境缺失动态库，程序会直接崩溃（找不到 `.so`）。
    - 注：Linux 下动态库为 `.so` (Windows 为 `.dll`)
