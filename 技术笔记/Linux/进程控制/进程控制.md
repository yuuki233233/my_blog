# 1. 进程创建：fork

在 Linux 中，`fork()` 是极其重要的系统调用。它从已存在的进程中创建应该新进程（子进程)，原进程为父进程

## 1.1 fork函数

在 `Linux` 中 `fork` 函数是非常重要的函数，它从已存在进程中创建一个新进程。新进程为子进程，而原进程为父进程
```c
// 子进程pid_t返回0，父进程返回子进程id，出错返回-1
#include <unistd.h>
pid_t fork(void);
```

>[!warning] 问题：
>1. 为什么要给子进程返回0，父进程返回子进程id
>2. 为什么一个函数fork会有两个返回值
>3. 为什么一个id即等于0，又大于0
>这些问题我们在上一章中，进程的概念中细讲过，这里我就简单回归一下

进程调用 `fork()`，当控制转移到内核中的 `fork()` 代码后，内核做：
- 当进程调用 `fork()` 陷入内核时，OS 会分配新的内存块和内核数据结构（PCB）
- 将父进程部分数据结构内容拷贝给子进程（比如父进程的PCB、地址空间、页表），把子进程加入系统调度链表
- 当 `fork` 返回时，父子进程共享了同一份代码，但执行流分叉了
- 父进程需要子进程的 ID 去管理它，子进程可以通过 0 知道自己是被创建出来的

![](图片/子进程的创建.png)

当一个进程调用 `fork` 之后，就有两个二进制代码相同的进程。而且它们都运行到相同的地方。但每一个进程都将可以开始执行它们自己代码，如下：
```bash
[zjh@izj6cd3zr5adf6jnm3mwihz lesson17]$ cat fork.c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main()
{
    pid_t pid;
    
    printf("Before: pid is %d\n", getpid());
    if((pid = fork()) == -1)
    {
        perror("fork()");
        return 1;
    }

    printf("After: pid is %d, fork return %d\n", getpid(), pid);
    sleep(1);

    return 0;
}

[zjh@izj6cd3zr5adf6jnm3mwihz lesson17]$ ./code
Before: pid is 18404
After: pid is 18404, fork return 18405
After: pid is 18405, fork return 0
```

这里看到三行输出，第一行 before，第二行 after。进程 18404 先打印 before 消息，然后又打印 after。另一个 after 消息有 18405 打印。注意到进程 10805 没有打印 before，原因如下表：
![](图片/子进程的id打印.png)

所以，`fork` 之前父进程独立执行，`fork` 之后，父子两个执行流分别执行。注意，`fork` 之后，谁先执行由调度器决定

## 1.2 写时拷贝 (Copy-On-Write)

父子进程的代码和数据是共享的，当任意一方写入，便以写实拷贝的方式各有一份副本`fork` 之后，父子进程的代码和数据通常是**共享**的（只读状态）。只有当任意一方试图**写入**数据时，OS 才会触发中断，真正在物理内存中拷贝一份副本，并将页表重新映射。如下图：

![](图片/写实拷贝.png)
写实拷贝的好处：
1. 通过虚拟地址寻找物理地址，当一个进程不需要执行时，虚拟地址指向的物理地址就只需挂起状态即可（节省内存）
2. 当创建子进程时，父子进程的数据段会变成只读状态，通过只读数据中修改的报错，来拷贝一份副本，将数据的只读改为可读可写（通过只读的报错拷贝副本）
3. 虚拟地址通过页表来查询物理内存，页表可以进行指向的修改，让虚拟地址不直接等于物理地址（减少耦合性）
4. 如果子进程只是调用 `exec` 执行新程序，或者在 `fork` 后只读数据，OS 就省去了大量无意义的内存拷贝，极大提高了效率。这就是进程独立性的技术保证

## 1.3 fork常规用法和失败原因

**用法**：
- 一个父进程希望复制自己，使父子进程执行不同的代码段。例如：父进程等待客户端请求，子进程处理请求
- 一个进程要执行一个不同的程序。例如：子进程从 fork 返回后，调用任意函数

**失败原因**：
- 系统中有太多进程
- 实际用户的进程数超过了限制

# 2. 进程终止：释放资源

进程终止的本质就是释放系统资源（PCB、代码、数据、打开的文件等）

## 2.1 退出场景

1. 代码跑完，结果正确（退出码 `0`）
2. 代码跑完，结果不正确（退出码 `非0`，不同数字代表不同错误原因）

Linux Shell 中的主要退出码：

| 退出码   | 解释                                        |
| ----- | ----------------------------------------- |
| 0     | 命令执行成功                                    |
| 1     | 通用错误代码                                    |
| 2     | 命令或参数使用不当                                 |
| 126   | 权限被拒绝或无法执行                                |
| 127   | 未找到命令或PATH错误                              |
| 128+n | 命令被信号从外部终止或遇到致命错误                         |
| 130   | 通过 `Ctrl+c` 或 `SIGINT` 终止（终止代码 2 或 键盘中断）  |
| 143   | 通过 `SIGTERM` 终止（默认终止）                     |
| 255/* | 退出码超过了` 0-255` 的范围，因此重新计算（超过 255 后，用退出取模） |
- 0：表示命令执行无误
- 1：不被允许操作。如在没有 sudo 权限的情况下
- 130：`SIGINT` 或 `^C` 和 `143`（`SIGTERM`）等终止信号时非常典型的，它们属于 `128+n` 信号，其中 `n` 代表终止码
- 可以使用 `strerror` 函数来获取退出码对应的描述

## 2.3 `exit()` vs `_exit()`

- `_exit(int status)`：纯正的系统调用。直接陷入内核，立刻释放资源，不刷新用户态缓冲区
- `exit(int status)`：C 库函数。它的内部也会调用 `_exit`，但在调用之前会做两件事：
	1. 执行用户通过 `atexit` 注册的清理函数
	2. **刷新所有打开的流（标准 I/O 缓冲区）**

![471](图片/执行exit过程.png)
区别：
- 进程如果 exit 退出的时候，`exit()`，进程退出的时候，会进行缓冲区的刷新
- 进程如果 exit 退出的时候，`_exit()`，进程退出的时候，不会进行缓冲区的额刷新

>[!note]
>测试题：`printf("hello"); _exit(0);` 屏幕上什么都不会打印
>换成 `exit(0);` 则会打印 `hello`

# 3. 进程等待：父进程的“收尸”责任

子进程退出后，如果没有父进程读取子进程的退出状态，子进程就会变成**僵尸进程（Zombie）**,占用内核的 PCB。`kill -9 [id]` 杀不死僵尸进程，因为僵尸已经死了。父进程必须通过进程等待来回收子进程

### 3.1 `wait()` 和 `waitpid()`

```c
// pid：子进程ID
// status：退出码
// options：信号类型
#include <sys/wait.h>
pid_t wait(int *status);
pid_t waitpid(pid_t pid, int *status, int options);
```

- `wait()`：阻塞等待任意一个子进程退出
- `waitpid()`：可以指定等待某个特定的子进程（`pid` 参数）。如果 `pid = -1`，则等同于 `wait`

![](图片/子进程出错返回.png)

### 3.2 核心解析：`status` 状态码

`status` 是一个**输出型参数**，由操作系统填充。如果传 `NULL` 表示不关心退出状态。  
`status` 是一个 32 位的整型，但真正有用的只有**低 16 位**：

- **正常终止**：
    - 低 8 位为 0（表示没有收到信号）
    - 高 8 位（`8~15` 位）为**退出码**
- **异常终止**：
    - 低 7 位为**终止信号编号**（如果有 `core dump`，第 7 位会被置为 1）
    - 高 8 位未使用

![](图片/子进程status位图.png)

**提取方法**：
```c
// 方法1：位运算
int exit_code = (status >> 8) & 0xFF; // 取退出码
int term_sig = status & 0x7F;         // 取信号

// 方法2：使用系统提供的宏（推荐）
if (WIFEXITED(status)) { // 判断是否正常退出
    printf("退出码: %d\n", WEXITSTATUS(status));
}
```

**代码演示**
```c
#include <stdio.h>
#include <errno.h>
#include <string.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main()
{
    // 创建子进程
    pid_t id = fork();
    if(id == 0)
    {
        int cnt = 3;
        while(cnt)
        {
            printf("我是一个子进程, pid : %d, ppid : %d\n", getpid(), getppid());
            sleep(1);
            cnt--;
        }
        exit(10);
    }

    // 父进程
    // 1. 子进程退出
    // 2. 子进程没退出
    
    int status = 0;
    pid_t rid = waitpid(id, &status, 0);
    if(rid > 0)
    {
        printf("wait success, rid: %d, exit code: %d, exit signal: %d\n", rid, (status>>8)&0xFF, status&0x7F); // rid
    }
    else
    {
        printf("wait failed: %d: %s\n", errno, strerror(errno));
    }

    return 0;
}
```

### 3.3 阻塞等待 vs 非阻塞等待

- **阻塞等待**：`options = 0`。父进程调用 `wait` 后，什么也不干，死等子进程退出
- **非阻塞等待**：`options = WNOHANG`。父进程调用 `waitpid` 后，如果子进程没退出，`pid_t` 立刻返回 0。父进程可以去干别的事，循环轮询（`do...while`）子进程的状态。这是服务器并发编程的常用手法



阻塞等待：如用 scanf / cin ，必须等待键盘输入数据，不然进程一直阻塞

```c
int main()
{
	pid_t pid;
	pid = fork();
	if (pid < 0) {
		printf("%s fork error\n", __FUNCTION__);
		return 1;
	}
	else if (pid == 0) { //child
		printf("child is run, pid is : %d\n", getpid());
		sleep(5);
		exit(257);
	}
	else {
		int status = 0;
		pid_t ret = waitpid(-1, &status, 0);//阻塞式等待，等待5S
		printf("this is test for wait\n");
		if (WIFEXITED(status) && ret == pid) {
			printf("wait child 5s success, child return code is
				: % d.\n",WEXITSTATUS(status));
		}
		else {
			printf("wait child failed, return.\n");
			return 1;
		}
	}
	return 0;
}
```


非阻塞等待，进程每隔一段时间，取一次子进程的状态，无需父进程一直等待，可以让父进程，做自己的事情

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
#include <vector>

typedef void (*handler_t)(); // 函数指针类型
std::vector<handler_t> handlers; // 函数指针数组

void fun_one() {
	printf("这是⼀个临时任务1\n");
}

void fun_two() {
	printf("这是⼀个临时任务2\n");
}

void Load() {
	handlers.push_back(fun_one);
	handlers.push_back(fun_two);
}

void handler() {
	if (handlers.empty())
		Load();
	for (auto iter : handlers)
		iter();
}

int main() {
	pid_t pid;
	pid = fork();
	if (pid < 0) {
		printf("%s fork error\n", __FUNCTION__);
		return 1;
	}
	else if (pid == 0) { // child
		printf("child is run, pid is : %d\n", getpid());
		sleep(5);
		exit(1);
	}
	else {
		int status = 0;
		pid_t ret = 0;
		do {
			ret = waitpid(-1, &status, WNOHANG); // ⾮阻塞式等待
			if (ret == 0) {
				printf("child is running\n");
			}
			handler();
		} while (ret == 0);
		if (WIFEXITED(status) && ret == pid) {
			printf("wait child 5s success, child return code is :%d.\n",
				WEXITSTATUS(status));
		}
		else {
			printf("wait child failed, return.\n");
			return 1;
		}
	}
	return 0;
}
```

# 4. 进程程序替换

`fork()` 创建的子进程通常执行父进程的代码分支。如果我们想让子进程执行**一个全新的程序**呢？这就需要用 `exec` 系列函数

**核心原理**：进程调用 `exec` 函数时，OS 会把磁盘上的新程序加载到该进程的地址空间，**完全覆盖**原有的代码和数据，并重置页表。这个过程**不创建新进程**，所以调用前后该进程的 PID 不变

![](图片/进程替换原理.png)

## 4.1 exec系列接口

```c
 #include <unistd.h>

       extern char **environ;

       int execl(const char *path, const char *arg, ...);
       
       int execlp(const char *file, const char *arg, ...);
       
       int execle(const char *path, const char *arg,
                  ..., char * const envp[]);
                  
       int execv(const char *path, char *const argv[]);
       
       int execvp(const char *file, char *const argv[]);
       
       int execvpe(const char *file, char *const argv[],
                   char *const envp[]);
```

共有 6 个以 `exec` 开头的函数，命名规律如下：
- `l` (list)：参数以列表（可变参数）形式给出，必须以 `NULL` 结尾
- `v` (vector)：参数以字符串数组形式给出
- `p` (path)：自动在环境变量 `PATH` 中搜索程序，无需写全路径
- `e` (envp)：自己维护（传入）环境变量

```c
#include <unistd.h>

int main()
{
	char *const argv[] = {"ps", "-ef", NULL};
	char *const envp[] = {"PATH=/bin:/usr/bin", "TERM=console", NULL};
	
	execl("/bin/ps", "ps", "-ef", NULL);
	
	// 带p的，可以使⽤环境变量PATH，⽆需写全路径
	execlp("ps", "ps", "-ef", NULL);
	
	// 带e的，需要⾃⼰组装环境变量
	execle("ps", "ps", "-ef", NULL, envp);
	
	execv("/bin/ps", argv);
	
	// 带p的，可以使⽤环境变量PATH，⽆需写全路径
	execvp("ps", argv);
	
	// 带e的，需要⾃⼰组装环境变量
	execve("/bin/ps", argv, envp);
	
	exit(0);
}
```

| 函数名      | 参数格式 | 是否带路径 | 是否使用当前环境变量 |
| -------- | ---- | ----- | ---------- |
| `execl`  | 列表   | 否     | 是          |
| `execlp` | 列表   | **是** | 是          |
| `execle` | 列表   | 否     | 否（需传 env）  |
| `execv`  | 数组   | 否     | 是          |
| `execvp` | 数组   | **是** | 是          |
| `execve` | 数组   | 否     | 否（需传 env）  |

### 2. execlp接口

```c
 int execlp(const char *file, const char *arg, ...);
```
`p` -> `PATH`，查找系统命令

```c
execlp("ls", "ls", "-l", "-a", NULL);
```
- `const char* file`：执行文件名（因为 execlp 会自动在环境变量 PATH 中查找指定的命令）
- `const char *arg`：执行的命令行

### 2.1 字符串的读写

使用C语言中的`scanf()` 和 C++中的 `cin<<`，会省略空格

如要解决，可选择用 `fgets()` 函数，
fget()函数的优点：
1. 可以字符串的方式输入
2. 可等待用户输入
3. 可利用函数清理换行

```cpp
#define COMMAND_SIZE 1024

{

    char *c = fgets(out, size, stdin); // stdin输入到out
    if(c == NULL) return false;
    
    if(strlen(out) == 0) return false; // 用户输入回车
    return true;
}

int main()
```

## 第四步：执行命令

需要创建子进程来执行命令，需用到 `execl` 接口

```cpp
#include <sys/types.h>
#include <sys/wait.h>

#define MAXARGC 128
char *g_argv[MAXARGC];

int Execute()
{
    pid_t id = fork(); // 创建子进程
    if(id == 0)
    {
        // child
        execvp(g_argv[0], g_argv); // 执行命令
        exit(1);

    pid_t rid = waitpid(id, nullptr, 0); // 子进程结束，子进程变成僵尸进程，需要被父进程接受
    (void)rid; // rid 使用一下
    return 0;
```

```cpp
// 获取用户输入的命令
bool GetCommandLine(char *out, int size)
{
    // ls -a -l => "ls -a -l" 字符串
    char *c = fgets(out, size, stdin);
    if(c == NULL) return false;
    out[strlen(out)-1] = 0; // 清理\n
    if(strlen(out) == 0) return false; // 用户输入回车
    return true;

// 3. 将字符串"ls -a -l" 拆成 "ls" "-a" "-l"
bool CommandParse(char *commandline)
{
#define SEP " "
    g_argc = 0; // 保证每次 g_argc = 0
    // 命令行分析"ls -a -l" 拆成 "ls" "-a" "-l"
    g_argv[g_argc++] = strtok(commandline, SEP);

    // 循环切完命令的每一个参数，填入g_argv里
    while((bool)(g_argv[g_argc++] = strtok(nullptr, SEP)));

    // 因为g_argc为后置++，把尾部的NULL也带上了，需要减去一个
    g_argc--;
    return g_argc > 0 ? true : false;
}

int Execute()
{
    pid_t id = fork();
    if(id == 0)
    {
        // child
        execvp(g_argv[0], g_argv); 
        exit(1);
    }

    // father   
    pid_t rid = waitpid(id, nullptr, 0);
    (void)rid; // rid 使用一下
    return 0;
}
```
